# ANTAR ROADMAP

**Status:** Living Document  
**Last Updated:** August 2026

---

# Purpose

This roadmap describes the major stages required to take Antar from product vision to a validated mobile application.

It is intentionally outcome-oriented.

Detailed implementation tasks should live in the relevant product, design, architecture, or engineering plans.

---

# Phase 1 — Product Foundation

**Status:** Complete

Outcomes:

- Product vision defined
- Identity established
- Experience principles documented
- Personas defined
- Product principles documented
- Information architecture established
- Version 1 scope defined
- Product scenarios documented
- Core system specifications drafted

# Phase 4 — Component System

**Status:** Next

Outcomes:

- Identify components emerging from approved experiences
- Define shared component responsibilities
- Define variants and states
- Map semantic design tokens
- Document accessibility behavior
- Build the initial Figma component library

# Current Focus

The current focus is:

> Build the Component System from the approved Design Foundations and Core Experience specifications.

The initial component inventory should emerge from the experiences rather than being invented independently.

---

# Roadmap Principle

Antar should move forward through validated layers:

```text
Vision
↓
Product
↓
Experience
↓
Design
↓
Components
↓
Prototype
↓
Architecture
↓
Implementation
↓
Validation
↓
Launch
```

Each phase may refine earlier work.

No phase should silently override an approved principle or product decision.
