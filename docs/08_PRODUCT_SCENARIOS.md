# Purpose

Product Scenarios describe the real-life situations in which people use Antar.

Unlike Personas, which describe **who** our users are, Product Scenarios describe **why** they open the application and what they hope to accomplish.

Every feature should improve at least one Product Scenario.

If a proposed feature does not clearly support an existing scenario—or justify the creation of a new one—it should be reconsidered.

---

# Product Philosophy

People do not open Antar to use software.

They open Antar because they are seeking something.

Sometimes they seek peace.

Sometimes guidance.

Sometimes discipline.

Sometimes understanding.

The application exists to support those moments with simplicity, clarity, and respect.

# How to Use This Document

Every proposed feature should answer three questions.

## 1.

Which Product Scenario does it improve?

---

## 2.

How does it improve that scenario?

---

## 3.

Does it align with Antar's Product Principles?

If the answer to any of these questions is unclear, the feature should be reconsidered.

---

# North Star

Antar should never encourage people to spend more time inside the application.

Instead, it should help them carry more wisdom into life outside of it.

The application is successful when its teachings continue long after the screen is turned off.
